# Adaptive shared-phrase bulk compression

Each archive represents one complete original column and reconstructs its exact bytes in original order. LFs remain ordinary reconstructed bytes, preserving row boundaries and any final unterminated row. Bulk omits row directories and does not expose selective-row reconstruction.

The encoder first validates five exact typed representations: fixed-prefix decimal identifiers, fixed-width two/four-symbol strings, canonical hexadecimal integers, UUID strings with a verified constant template, and bounded coordinate strings. Every prefix, alphabet and template constant needed for reconstruction is stored in that column's archive. Records retain their original order. Typed decoding uses decimal tables derived at setup, nibble unpacking, a four-integer hex batch path, and SSSE3 UUID template filling with three overlapping 16-byte stores contained within each 37-byte row.

For remaining text, automatic OnPair+ fitting supplies maximum 16-byte phrases. The new representation removes unused symbols and the baseline grammar. A bottom-up cost pass splits rare phrases into their learned children whenever token stream plus unshared dictionary cost decreases. Used symbols receive dense 16-bit IDs. A substring-sharing pass visits longer symbols first and lets contained symbols reference existing pool bytes. Each descriptor is one 32-bit word containing a 24-bit pool offset and8-bit decoded length. The pool includes32 charged padding bytes for wide loads.

The encoder measures how much original data is represented by 12–16-byte phrases after pruning. If this is more than 60%, it runs one additional pair pass: count adjacent token pairs, consider those occurring at least 12 times with combined length at most32, rank positive savings by `2*frequency - combined_length -4`, and admit at most 8192 pairs subject to16-bit dictionary capacity. A deterministic left-to-right rewrite merges admitted pairs, unused entries are removed again, and substring sharing includes32-byte symbols. This step may cross LF boundaries, which is valid for complete-column reconstruction. The archive selects a16-byte or32-byte expansion kernel. On the supplied corpus this criterion enables the32-byte extension for URLs.

The encoder also constructs a complete LZ4HC level 6 candidate for each untyped column and stores the smaller complete archive. The generic 32-byte header records magic, mode, original length and dictionary/token counts. Mode 0 stores 16-byte-max phrases, mode 1 stores whole-column LZ4HC, and mode 2 stores 32-byte-max phrases. No file names or column identities are used for selection.

`lab_open` validates framing and retains archive pointers; it does not expand a grammar or decode/cache a column. Phrase reconstruction reads four descriptors at a time and copies16 or32 bytes from the shared pool, advancing by exact lengths. The tail checks output capacity and performs exact-length copies when necessary. HC6 calls the separately pinned LZ4 library. Native decoder code, embedded format constants and all dictionary/padding bytes are charged.

All validation, fitting, pruning, pair counting, remapping, sharing, HC6 compression and final archive selection execute inside `lab_encode`. There is no offline data-dependent stage and no auxiliary reconstruction artifact. Data-independent g++ builds are recorded separately in BUILD_TIMING.json. SSSE3 is a CPU capability requirement, not an uncharged library. Pinned LZ4 is excluded only under the standard-codec-available convention and remains included in strict deployment total.

The operating configuration is fixed and automatic for all 23columns. Claims require full Lab qualification and matched-server measurements; agent-container timing is development evidence only.
