# Researcher workflow

Start with `brief`. Its `run_configuration` resolves the immutable dataset card, and its `search_contract` gives the current instructions. New research defaults to compression software written from scratch for the entire supplied dataset, including a working encoder, independent decoder, reproducible build and documented interface. Legacy split cards remain explicit in the returned configuration.

The normal sequence is data inspection, a concise hypothesis, native implementation, focused development checks, full evaluation, then a selected result and export. `record_hypothesis(statement, expected_benefit, falsifier)` returns an immutable receipt; put its `experiment_id` in `candidate.json` under `hypothesis`. Record it before substantive implementation. The receipt verifies that the hypothesis predates registration; it does not prove when source editing began.

`manifest_template(name)` supplies a complete C++ v2 manifest with no codec source. Implement the four interfaces described in `CANDIDATE_ABI.md`. Understand every changed line and the full preparation, encoding and reconstruction path. Deliver clean software with the best measured performance possible within the objective and budget. Obey `COMPRESSION_LAB_THREADS` and the aggregate memory limit. Use efficient data layout, minimize repeated scans and copies, and measure bottlenecks. Preserve the decoder's validity checks and independent reconstruction.

Register source inside the public workbench and evaluate the returned digest. Poll the returned job ID. Use `feedback(result_id)` for one result, or `compare(result_ids=[reference, candidate], diagnostics=True)` for paired full results. The CLI HTTP helper uses those same names and JSON arguments without aliases. If the benchmark lease is busy, preserve work and retry after contention clears.

Baselines are available when the card exposes them. Recipe creation is available only in open implementation mode; from-scratch runs implement their own mechanism. The absence of a baseline table is not a measurement or a reason to seek owner files.

Screens and quick runs guide search. Final compression claims require the complete full evaluation, all required gates and seven timing trials. Deliver at least one fast mode with the best measured combination of speed and compression. The 100 MB/s end-to-end floor is a bare minimum; continue optimizing well above it. Also pursue maximum compression: if the densest approach is too slow, retain and optimize that separate mode alongside the fast mode. Use the configured primary size metric consistently and retain the strict decoder deployment total. Report measured tradeoffs between size, all encoding stages, decoding speed and memory, with separate result IDs and exports for each mode.

New cards allow offline fitting and preprocessing under `offline-plus-online-v1`. Declare the reproducible offline role in `CANDIDATE_ABI.md`, including compilation of dataset-dependent generated code when needed. The evaluator starts from raw fitting input, checks reproduced artifact bytes and runs online encoding with fresh artifacts. Report offline, online and paired combined time from `encoding_stages` and the raw trials. New cards use `encoding_floor_scope: combined`, so every dataset-dependent preparation step counts toward the 100 MB/s end-to-end minimum. A cached lookup cannot omit the work required to build its archive. Legacy cards keep their sealed timing contract.

Use available research time for deeper mechanism analysis and concrete, falsifiable improvements to both speed and compression. Reserve time to validate, export and explain the strongest measured candidates and deliver usable software. Follow the configured completion rules. A failed round must continue while the configured time, money and additional-round allowances remain; any exhausted limit permits a measured negative outcome. Provider capacity retries do not consume research rounds.

Use the completion method returned by `brief`. With `controller_finish`, export both selected modes, prepare the report and checkpoint, then call `finish` with the qualified fast result when available and inspect its receipt. With `export_and_report`, export the result, write `workbench/agent/RESULT.md` and `CHECKPOINT.md` with result IDs and export paths, and return them to the supervisor. Qualification alone is not completed delivery. When no candidate qualifies, preserve the strongest correct result and state why.

Model, effort, delegation and the wall-clock allowance come from the commissioned campaign. Preserve them on continuation; do not inherit those settings from an old prompt. Mutable-store experiments use their separate store protocol and operation metrics.
