# Completion and capacity retries in 0.6.0

Configure the completion controller before preparing the researcher prompt. The Prime RPC runner requires protocol version 2, checks the commissioned model and child limits, and uses committed lab results to decide whether another research round is needed. A natural-language final answer alone does not close a failed experiment. Protocol version 1 remains available for reproducing historical runs; `--probe-only` explicitly runs the old lifecycle probe without goal supervision.

`examples/completion-protocol.json` permits three additional unsuccessful research rounds and a shared USD 50 cap. Any configured limit can end the run. Set `time_limit_seconds` to an integer duration, or supply `deadline_epoch`; the deadline is resolved once at configuration and survives restarts. Set `max_cost_nano` to the dollar cap multiplied by 1,000,000,000. Set `max_failure_continuations` to the number of additional rounds after the initial round. Null or omitted limits are disabled; at least one must be supplied. Evaluator admission limits on the sealed card also remain binding. `stop_on_success` is false in the example: clearing a minimum gate leaves room to improve compression and speed. The owner can explicitly enable it for a commission that should close as soon as committed full evidence meets the objective.

For example, a 3,600-second time limit alone uses `time_limit_seconds: 3600` with both other limits null. An attempts-only run uses `max_failure_continuations: 3` with both other limits null. Repeated finish requests, polls, development tests and provider retries do not each consume a research continuation. Continuations are claimed durably before dispatch; native transcript receipts acknowledge delivery. The final allowed round can still evaluate and deliver its handoff. A qualified result found on the last round remains retained as qualified evidence.

Launch preparation with `python tools/prepare_agent.py --workspace /absolute/new-work --protocol /absolute/protocol.json`. Run the trusted `tools/prime_rpc_check.py --campaign /absolute/campaign.json` driver outside the agent sandbox. The campaign retains its existing runtime, profile, model, native-home, resource and MCP fields. `prime_launcher` and `kernel_python` optionally preserve commissioned immutable launch wrappers without rewriting the runner. A protected `budget_ledger` path is required when a monetary limit is configured. The driver invokes controller operations under the workspace evaluator UID when its own UID differs; the model receives only the public MCP interface.

The monetary meter includes all root, child, compaction and retry requests sharing its ledger, including outstanding reservations and unknown charges. Its cap must equal the controller cap. Every paid request is independently reserved by the private gateway before dispatch; native SDK cost estimates do not authorize spending. A fully reserved request can settle before the controller decides whether funds remain. The bundled `tools/openai_budget.py` preserves the commissioned Luna/Sol standard pricing profile and USD 50 maximum, checked on 2026-09-11; other pricing or larger commissions need their own reviewed meter configuration. No money cap can be enforced from an unmetered subscription usage estimate.

The private `tools/openai_gateway.py` owns capacity retries: one initial request, then waits of **15, 30, 60, 120, 180 and 300 seconds** before six retries. Configure the native profile with `retry.enabled: false` and `retry.provider.maxRetries: 0` so the SDK does not multiply these attempts. The gateway distinguishes structured overload errors from authentication, quota, slowdown and unknown transport failures. A configured deadline, operator disable, disk reserve or insufficient remaining funds may stop retries sooner. Inference itself retains the commissioned absence of an API timeout.

Each generation attempt has a separate durable budget reservation and metadata receipt. If a capacity failure has valid usage, it is charged; otherwise its entire reservation remains as `capacity_hold` while a separately funded retry may proceed. Existing uncertain or invalid-usage tickets are never silently cleared or reclassified. Failed-attempt output is buffered privately and discarded, preventing partial tool calls and response IDs from being mixed into the successful retry. Only a settled successful/incomplete response is delivered to the native client. Buffering delays native streaming updates; keepalives keep the connection open.

Use the matching `tools/openai_guardian.py` for the commissioned service layout. It understands retained capacity reservations and distinguishes a controller-completed run awaiting owner audit from an infrastructure fault. Its service never advances experiments itself. The private gateway control accepts an optional `deadline_epoch`, matching the controller's resolved deadline, to stop backoff admission after the time allowance expires.

Primary source, accessed 2026-09-11: [OpenAI API error codes](https://developers.openai.com/api/docs/guides/error-codes). The exact six-delay policy comes from this commission. The retry and goal regression tests inject provider failures and use real local JSONL/SDK session machinery without paid API calls. These controls enforce recorded acceptance gates and completion budgets; they do not prove that every possible codec bug has been found.
