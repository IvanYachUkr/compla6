# Audit repairs in 0.5.7

This release preserves 0.5.6 and its recorded results. It changes the evaluator's bounded correctness fixtures, Linux thread accounting, native RPC lifecycle observation and generated workflow guidance. It contains no researcher candidate implementations or baseline results from the audit that prompted these fixes.

The bytes adapter now derives small valid cases from the beginning of at most two public corpus objects, including lexical JSON variations when applicable. Original bytes, missing final newlines, whitespace and nested key ordering are tested without changing the scored corpus. All generated cases remain bounded. The full unsanitized mutation sequence now also covers a representative encoded fixture payload, exercising opaque fallback paths. This broadens the bounded gates; it is not a proof for all inputs.

Linux can retain terminating tasks after `pthread_join` wakes. Setting `RLIMIT_NPROC` to the declared workers plus the namespace waiter falsely rejected successive legal worker pools. The runtime retains a finite emergency ceiling of 128 tasks, seccomp process-creation denial, the commissioned CPU affinity and memory limits. Polling enforces the declared number of live native tasks, excluding `PF_EXITING` and dead/zombie tasks; the original kernel task counts remain recorded separately. Polling can miss transients and is not an exact per-clone kernel limit.

Primary sources consulted 2026-09-11: [pthread_create](https://www.man7.org/linux/man-pages/man3/pthread_create.3.html), [pthread_join](https://www.man7.org/linux/man-pages/man3/pthread_join.3.html), [getrlimit](https://www.man7.org/linux/man-pages/man2/getrlimit.2.html), [proc_pid_stat](https://www.man7.org/linux/man-pages/man5/proc_pid_stat.5.html), Linux v7.0 [exit.c](https://raw.githubusercontent.com/torvalds/linux/v7.0/kernel/exit.c) and [sched.h](https://raw.githubusercontent.com/torvalds/linux/v7.0/include/linux/sched.h). The exit-cleanup explanation is an inference from the documented limits and kernel ordering, supported by the real pthread reproducer.

The RPC driver preserves active lifecycle state across read-only `get_state` probes. It checks native state every five seconds without invoking a model. If `agent_end` was lost, completion requires both explicit native quiescence and a fresh terminal assistant message persisted in the verified owned session. Old stops, active/new messages, partial transcript tails, different sessions and escaped profile paths do not establish completion. Transcript contents are streamed and never exported by this check. Generated instructions now explicitly require polling asynchronous evaluation jobs to a terminal result; automatic wake-up is not assumed.

Validation receipts under `results/` retain the failed reproductions and subsequent checks. The first resource patch still failed two worker-reuse tests because it counted exiting tasks; the corrected run passed all 13 native resource, fixture and full-gate checks, including optimized and ASan/UBSan runs of 100 joined pools, excess-thread termination, process/network/affinity denial and a full native codec gate. The RPC, observer and instruction tests passed 39 checks, including real JSONL subprocess integration with a missing terminal event and a later active turn. One earlier command named a nonexistent test module; that command error is retained and is not a product failure. Installed-runtime verification is recorded separately in `results/current-release.json`.

Benchmarks from different release fingerprints remain distinct. Never reinterpret old result IDs as passing these new gates or directly merge their timing identities.
