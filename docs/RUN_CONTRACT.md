# Research and timing contract, 0.6.0

Build byte-exact lossless compression software from scratch for the complete supplied dataset: a working encoder, independent decoder, reproducible build, documented command-line interface and usable modes. Established algorithms may be implemented from first principles; scientific novelty is not required. An explicitly commissioned open implementation policy may permit existing codec libraries. The sealed card is the scientific authority, and `brief`, generated prompts and public tools resolve that same configuration. Existing releases, workspaces, prompts and results retain their original contracts.

Pursue high speed and maximum compression together. At least one fast mode must compress the raw supplied input at 100 MB/s end to end or better. This is a bare minimum for acceptance, not sufficient performance or a reason to stop optimizing; seek substantially higher speed and better compression within the commissioned budget. If the densest approach cannot reach the floor, optimize it as a separate maximum-compression mode and develop a fast mode with the best measured combination of compression and speed. One mode may satisfy both objectives. Preserve and explain measured size, end-to-end speed, online speed, offline preparation, decoding and memory tradeoffs for each selected mode. A correct slower mode is useful evidence but cannot replace a qualified fast result.

New cards use whole-dataset evaluation, from-scratch implementation, `offline-plus-online-v1` and `encoding_floor_scope: combined`. Offline fitting and preprocessing may be slow, but every dataset-dependent operation from raw input to finished archive counts toward end-to-end speed, including required generated-code compilation. A fitted v2 candidate supplies a reproducible native offline role; fresh artifacts and rebuilt binaries must match the registered bytes. Seven offline measurements are paired with seven online measurements, and combined nanoseconds are summed within each pair before aggregation. The floor and noise rule use combined timing. A codec without offline work reports zero preparation and equal online/combined time. Data-independent builds and evaluator overhead are disclosed separately. Source review must establish that the declared stages include every required operation; archive replay does not erase its preparation cost.

Keep code clean, cohesive and efficient. Understand every changed line and the full data path, use bounded memory and efficient data layout, and optimize measured bottlenecks. Before substantive implementation, record the hypothesis, expected benefit and falsifier and describe the format, steps, assumptions and failure cases. The immutable hypothesis receipt proves recording before registration, not before source editing. Use focused development checks, then every required full correctness, independence, corruption, diagnostic, resource and reproducibility gate plus all seven timing trials. Screens and quick runs cannot qualify a final result.

New reporting uses `standard-codec-available-v1`, subtracting only separately pinned standard codec library files actually present in the independent decoder inventory. Payloads, framing, custom binaries, dictionaries, learned artifacts and other required reconstruction information stay charged. Preserve the strict decoder deployment total beside the primary score. Static codec code has no automatic deduction. Rank qualified fast candidates by the declared charged size, and retain the size/speed frontier and strongest correct dense alternative with separate result IDs and exports.

Completion protocol version 2 accepts a time limit, money limit, additional failure-round limit, or a combination; any exhausted limit can stop the run. A failed final answer cannot close research while configured allowances remain. Three continuations mean the initial research round plus at most three additional failed research rounds, not three evaluator calls. The controller continues after qualification by default, allowing more speed and compression improvements; an explicit owner `stop_on_success` override remains available. The trusted gateway separately controls six provider-capacity retries. See [completion controls](COMPLETION_CONTROLS.md) for exact accounting, delays and launch requirements.

Finish with the configured method after exporting the selected modes and writing a report/checkpoint with their IDs, paths and tradeoffs. A controller success requires a compatible full agent result passing the fast floor; a baseline result, recipe, screen, export or natural-language claim is insufficient. Failed attempts and limitations remain recorded. No model calls participate in the evaluated codec pipeline, and no previous scientific dataset or model run is reused as a release test fixture.
