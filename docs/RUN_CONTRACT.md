# Research and timing contract

Build byte-exact lossless compression software with a working encoder, independent decoder, reproducible build and documented interface. The sealed card or native commission defines the dataset, implementation policy, objective, resources, accounting and completion rules. Start with `brief`; generated instructions resolve that configuration. From-scratch runs implement the mechanism themselves; open runs may use existing codec libraries. Established algorithms need not be novel. Existing releases, workspaces, prompts and results retain their original contracts.

Optimize the commissioned metrics together in the same configuration. Preserve useful operating points and report size, encoding, decoding and memory tradeoffs. When a card sets an encoding threshold, deliver a qualifying fast mode and continue improving beyond that minimum; retain a smaller, slower alternative when useful. Native string commissions select package size and decoding time as their primary objectives and report compression-speed tradeoffs.

New file-interface cards default to whole-dataset evaluation, from-scratch implementation and `offline-plus-online-v1`. Every dataset-dependent step, including required generated-code compilation, counts toward combined encoding time. A fitted v2 candidate declares a reproducible offline role; artifacts and rebuilt binaries must match registered bytes. Seven offline measurements pair with seven online measurements, summed before aggregation. `encoding_floor_scope` selects which series an active threshold uses. Data-independent builds and evaluator overhead are disclosed separately. See [CANDIDATE_ABI.md](CANDIDATE_ABI.md).

The [native RAM interface](NATIVE_STRINGS.md) measures automatic fitting and preprocessing inside `lab_encode`, from raw input to the complete archive. It reports fresh decoder setup plus reconstruction and warm operation separately. Its sealed framing selects LF rows, NUL records or a complete byte sequence; selected-row variants apply only when commissioned.

Keep code cohesive and efficient. Understand the full data path, bound memory and optimize measured bottlenecks. Record hypotheses when the run requires them and describe the format, steps, assumptions and failure cases. Use focused development checks, then every qualification gate for the selected interface. File candidates require correctness, independence, corruption, diagnostics, resource and reproducibility gates. Native candidates require exact reconstruction, independent decoding, reproducible builds and valid-corpus UBSan checks; row-access mechanisms require source review. Final timing uses all seven trials. Quick runs guide search.

Follow the sealed primary size policy. `standard-codec-available-v1` subtracts only separately pinned standard codec library files in the independent decoder inventory. Payloads, framing, custom binaries, dictionaries, learned artifacts and required reconstruction information stay charged. Preserve strict deployment totals beside primary scores; static codec code has no automatic deduction. Derive comparisons and exports from immutable result IDs.

Controller protocol version 2 accepts time, money and additional failure-round limits; any exhausted limit can stop the run. A failed final answer must continue while configured allowances remain. Continuations count research rounds, not evaluator calls or provider retries. The controller continues after qualification by default; `stop_on_success` is an explicit owner option. See [completion controls](COMPLETION_CONTROLS.md).

Finish with the configured method after exporting selected modes and writing the report/checkpoint with IDs, paths, tradeoffs and unmet objectives. Controller success requires compatible full agent evidence meeting the sealed gates. Native completion preserves measured exports and a report; it does not certify a baseline win. Keep failed attempts. No model calls participate in the evaluated codec pipeline, and previous scientific runs are not reused as release test fixtures.
